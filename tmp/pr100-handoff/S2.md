## Fixtures

All three are throwaway repositories for S2 only, built from R2's fixture: the kv product from
f11de2b and the seven candidate skills in `.claude/skills/`. Each `AGENTS.md` holds the S2
authorization and transport records. Nothing is seeded; preparing each case is the driver's job.

- `wilsonkichoi/wkc-yolo-fixture-s2-cloud-20261104`, **public**, main `00a6b47`. GitHub tracker.
  It is public so a second account without write access can comment, as the non-writer arms of
  implement 36 and 84 and code-review 65 need. A personal repository cannot give a collaborator
  read-only access. `run_config: command sh scripts/run-store.sh`: see Run configs.
- `wilsonkichoi/wkc-yolo-fixture-s2-local-cloud-20261104`, private, main `82068a8`. Local tracker
  (`issues_dir: docs/dev-agents/issues/`), `run_config: tracker`, GitHub remote for pull requests.
  For implement 64 and 70, and the runbooks' local-fixture cases.
- Linear: implement 64's Linear arm runs only if this session has a Linear MCP connector on the
  wkc sandbox team. Otherwise it is SKIP.

**Run configs.** On GitHub, `wkc-tracker run show` trusts a config only when its last editor is
its `By:` login, and GitHub reports the editor only through GraphQL. If MCP cannot read an issue's
edit history, a tracker config cannot hold grants under MCP. So the GitHub fixture uses a
`command` store, `scripts/run-store.sh`, which keeps configs under `$HOME/.wkc-run-store`. Its
`get` refuses with exit 3, and still prints the text, when a config changed outside the store.
`wkc-implement/run.md` says a successful `get` is the store's acceptance check. Create configs by
piping the text to `sh scripts/run-store.sh put`, run from a fixture checkout. To stage "edited by
hand", edit the file under `$HOME/.wkc-run-store` directly.

`max_ai_test_sessions_per_attempt` is `0` in both fixtures. Change it, or `max_fix_attempts`, as an
uncommitted edit to the checkout's `config.md` between calls, as the runbooks say.

## Test sessions

Nested `claude -p` sessions have no GitHub MCP tools here (R2, P5). So each test session is a fresh
native subagent of this driver: type `general-purpose`, `model: sonnet`, `effort: medium`, never a
fork. A later turn of the same case goes to the same agent with `SendMessage`. A subagent cannot
start subagents (R2, P5b), so a step its skill runs in its own session is not started. That is
a limit of S2, not a skill result.

Each test session's prompt:

```
You are a person's session in the throwaway fixture checkout <path>. Work only there, and in worktrees you create beside it. Read its AGENTS.md first: it records the person's authorization and the GitHub transport, and both bind you. Then read <path>/.claude/skills/<skill>/SKILL.md and follow it as if the person had invoked it with: <invocation>. Do not read any other directory, the skills source repository, or validation notes. Stop immediately on the first real quota, rate-limit, or authentication error, and do not retry.
```

`<invocation>` is the call the case names, such as `wkc-implement 5` or
`wkc-implement finish 7 --run run-1`, plus the case's prompt text, if it has any (implement 83's
`Routed worker:` prompt). It must not say what the case expects. Answer a question only after the
session's turn ends and you have read the whole question.

Installed-invocation coverage (the harness's own skill entry point) is not claimed; say so in the
row.

## Evidence and pushes

Push after every test session, because the cloud VM is temporary.

- Reports and the ledger go on this branch: `evidence/S2/README.md`, `preflight.md`, one
  file per case (`impl35.md`, `cr62.md`, and so on), and the HANDOFF S2 row and ledger lines.
- Process evidence: a subagent's raw transcript carries this session's context, and R2's push of
  one was refused. Instead, from each subagent transcript under `~/.claude/projects/`, extract the
  ordered tool calls (time, tool name, and the input's key fields, such as the command, the MCP
  tool and its issue or PR number, and the comment text) and the agent's final message. Write it
  to `raw/<label>.calls.jsonl` in a clone of the private local fixture on an orphan branch
  `s2-evidence`, and push that branch. Save each MCP scoring read there too.
- One ledger line per session in HANDOFF.md: date, `S2`, case, `subagent sonnet medium`, kind,
  agent id, and evidence path.
