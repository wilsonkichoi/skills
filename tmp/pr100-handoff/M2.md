## Test sessions

Nested `claude -p` sessions have no GitHub MCP tools here (R2, P5). So each test session is a fresh
native subagent of this driver: type `general-purpose`, `model: sonnet`, `effort: medium`, never a
fork. A later turn of the same case goes to the same agent with `SendMessage`. A subagent cannot
start subagents (R2, P5b); every M2 case expects a session that starts no worker, so that limit
does not change a PASS list here.

Each test session's prompt:

```
You are a person's session in the throwaway project checkout <path>. Work only there, and in worktrees you create beside it. Read its AGENTS.md first, if it has one: it records the person's authorization and the GitHub transport, and both bind you. Then read <path>/.claude/skills/<skill>/SKILL.md and follow it as if the person had invoked it with: <invocation>. Do not read any other directory, the skills source repository, or validation notes. Stop immediately on the first real quota, rate-limit, or authentication error, and do not retry.
```

`<invocation>` is the case's call and its request text, if the case gives any. It must not say
what the case expects. Answer a question only after the session's turn ends and you have read the
whole question. Installed-invocation coverage is not claimed; say so in the row.
