0.0.8 2026-09-18T13:34:10-07:00 Add the `tracker` skill: one `SKILL.md` carrying the seven-status vocabulary (`backlog`, `ready`, `in-progress`, `in-review`, `done`, `cancel`, `duplicate`), eight verbs (`list`, `show`, `next`, `create`, `claim`, `comment`, `move`, `link`), and the ticket shape inline, plus one backend file per backend (`github.md`, `linear.md`, `local.md`) of which exactly one loads per session. On GitHub the four open states are labels and the three terminal states are native close reasons, so a closed issue carries no status label and an open issue with no label reads as `backlog`; `list backlog` therefore lists every open issue and keeps the unlabelled ones rather than filtering on the label. Dependencies are GitHub's native issue dependency edges, with no body-text fallback. Verbs that write now read first: `claim` requires exactly `ready` with no assignee before it edits, because `gh issue edit --remove-label` on an absent label exits 0 and would otherwise add `in-progress` beside `in-review`; `move` reads the current status and refuses to move out of a terminal state, because `gh issue close` on a closed issue exits 0 and silently keeps the original reason; `create` writes the ticket unlabelled, links its blockers, and applies the status last, so it never sits on the frontier before its edges exist. Verified against gh 2.97.0 that `blockedBy.totalCount` counts closed blockers as well as open ones, so the frontier query filters on `blockedBy.nodes[].state`, folds the 50-node cap into the jq, and lets a null `blockedBy` fail loudly rather than suppressing it into a permanently empty frontier. Lists are ordered server-side with `sort:created-asc` and treat a row count equal to `--limit` as incomplete, since `gh` returns newest first and would otherwise drop the lowest-numbered tickets `next` wants. Also verified that `stateReason: DUPLICATE` reads back from the `gh issue list` payload. `move <id> duplicate <original>` now carries the original's id. Linear resolves workflow states by type rather than by name, and stops rather than guessing when the MCP server exposes no relation tool. Local makes the frontmatter the only state anything reads, names `git config user.name` as the assignee, and compares ids numerically. `setup` now creates four status labels instead of seven, says the local backend is one session at a time, and points at `/tracker list` as the next step. Deletes the untracked half-ported `release` draft, which referenced a helper script and a workflow that do not exist here. Second review pass: the frontier jq now opens with an explicit `if .blockedBy == null then error(...)` rather than relying on the filters below it, because `null.totalCount` is `null` and `null.nodes | length` is `0` in jq, so a null row compared false against the 50-node check and was dropped silently at exit 0, which on a host without dependencies is a permanently empty frontier. Both filtering queries emit `rows`, the pre-filter count, since a full page that filters down to nothing is otherwise indistinguishable from an empty repository and the `--limit` rule had nothing to read. A session that loses the claim tie-break now removes only its own assignment and leaves the labels alone; stripping `in-progress` back to `ready` left the ticket assigned to the winner while reading as unclaimed. Linear reads `backlog` from every `triage` and `backlog` state, so a team whose new issues land in Triage does not hide the human-filed tickets `list backlog` exists to surface, and its `started` states resolve by workflow order rather than by name. Also states that the frontier is a candidate list rather than a set of facts, that `show` is the only verb reporting an issue with two status labels, that `create` takes an open status only and reports partial failure, and how `local` derives a slug, handles colliding ids, and writes frontmatter onto a hand-written file. Third review pass: `claim`'s GitHub pre-read requires exactly one status label rather than exactly the `ready` label, since a repository where every issue also carries `bug` would otherwise refuse every claim, and its re-read names the inconsistent label set as its own case. `move` removes every status label the read found instead of one guessed name, which makes it the repair for a ticket a human left carrying two. The terminal `list` gets its own jq so the `rows` truncation rule reaches it. The claim tie-break compares logins case-insensitively, because GitHub logins are. Linear gains the claim check it actually needs: its issues have a single assignee, so the multi-assignee race test cannot fire there and the re-read has to name you instead, with the remaining blind spot stated rather than papered over. A Linear state outside the seven is now reported by its own name and type instead of folding into `backlog`, which had made `show` call it `backlog` while `list backlog` never returned it, and the duplicate relation falls back to a comment when no relation tool exists. `local` no longer contradicts itself about the body: `link` keeps the `## Blocked by` section in step when the file has one and leaves a hand-written body alone when it does not.
